# Strategy Arena — 最中限

GPCC資料・公開二次資料に基づく最中限の実装。アルゴリズムを自由に戦わせ、短期のターン獲得と長期のゲーム勝率の違いを楽しむ実験環境。

原典全文との一致は未確認。初期プロンプトの17トリック・スートフォロー・固定3点制は採用しない。

- [ルール調査と未確定事項](docs/rules-research.md)
- [原典・研究資料と現行実装の監査](docs/rules-audit.md)
- [構成・実装計画](docs/architecture.md)

Python 3.12+ / uv / FastAPI / NumPy / SQLite と、React / TypeScript / Vite / pnpm / Tailwind CSS / shadcn/ui / Apache ECharts を使用する予定。

## 実装済み

- Pythonゲームエンジン、3ターン×5ラウンド、得点各層、共同勝利、完全リプレイ。
- Random / Greedy / Conservative / ScoreAware / Heuristic の5戦略と追加用レジストリ。
- 公開行動履歴、未知カード集合、一様な手札候補サンプリング。
- FastAPI・Reactの人間対戦とAI観戦、公開履歴・得点推移。
- 共通配札・全座席順による対戦、SQLite保存、勝率・分布・座席差のECharts可視化。
- アルゴリズム図鑑、戦略名からの簡易説明、実計算に基づく候補別の判断ログ。

## アルゴリズム図鑑と判断の見方

「アルゴリズム図鑑」タブで、登録戦略の考え方・判断手順・使用情報・特徴・ランダム要素・パラメータ・バージョン・実装方式を確認できる。対戦の戦略選択欄や戦略名のリンクから簡易説明を開き、「図鑑で詳しく見る」で移動できる。図鑑の解説は実装コードに基づく一般的な説明であり、実際の1手の判断ログとは区別している。

図鑑の下部にはSQLiteに保存された成績を表示する。ルール・情報条件・各戦略のバージョン・対戦相手構成・記録済み設定が異なる結果は別グループにする。成績がなければ「保存結果なし」、記録条件が不足していれば集計対象外として案内する。古い結果の未記録設定と、新しい結果の既定設定も混ぜない。

ゲーム開始前に「判断の詳細を記録」を有効にすると、公開履歴の下に「判断をたどる」パネルが表示される。

1. AIで1ターン進め、選択カード・実際の理由・候補別評価・判断前後の得点を見る。
2. 「前の判断」「次の判断」またはターン番号で履歴を切り替える。手札と得点も表示ターンに合わせる。対戦に戻るには「最新に戻る」を押す。
3. 「計算に使った値」を展開すると、候補評価の内訳を確認できる。「判断時点までの公開情報」には、その選択より前の公開札だけを表示する。
4. 相手の候補手札は対戦中には表示しない。ゲーム終了後に「全員の判断を分析表示」を押すと各プレイヤーの詳細を見られる。この分析表示は対戦時の情報条件を変更しない。

Randomは候補に点数を付けないため「評価なし」と表示する。理由や評価を提供しない戦略には架空の説明・数値を補わない。異なる戦略の評価値は尺度が異なり、0〜100への正規化や直接の強さ比較は行わない。

比較実験・大量対戦では詳細ログを既定で生成・保存しない。APIの `capture_details: true` またはCLIの `--capture-details` で明示的に有効化できる。詳細ログを保存したバッチの結果には `decision_trace` が付くが、保存バッチを図鑑画面から再生するUIはまだない。

説明付き戦略の登録方法・判断ログのインターフェースは [アルゴリズム図鑑・判断ログの仕様](docs/algorithm-guide.md) を参照。

## 同一局面でのアルゴリズム比較

1. 対戦テーブルでゲームを開始し、「同じ局面でAIを比較」を押す。
2. 「比較する局面」で現在の手番、または履歴の判断時点を選ぶ。「前の判断」「次の判断」や履歴のターン番号とも連動する。比較するのは常に**そのターンでカードを選ぶ直前**で、得点・手札・公開済みカード・合法手を確認できる。
3. 比較する戦略をチェックし、「比較の乱数シード」を指定して「この局面で比較する」を押す。
4. 同じカードを選んだ戦略のグループを見比べる。各戦略の「候補評価・計算内訳」を開くと、既存の判断表示と同じ形式で理由・評価・使用情報を確認できる。戦略名から図鑑の説明も参照できる。

対戦は進まず、通常対戦の手札・得点・戦略内部状態・乱数状態を変更しない。履歴の実際の選択とは別に、指定した比較シードで再判断する。判断情報を提供しない戦略も選択カードを比較でき、架空の理由や評価値は補わない。

対象席で実際に動いている戦略は現在の内部状態を複製し、過去局面では保存した初期状態と実際の履歴から復元する。他の戦略は登録された設定・学習済み値を持つ初期状態を使用する。これらの違いは各結果の「状態」に表示する。複製・復元できない戦略は、その理由を表示して他の戦略の比較を続ける。

対戦中はP1の視点。終了後に「他プレイヤー視点を開く」を押すとP2・P3の視点も選べる。各戦略へ渡すのは、選んだ対象者自身の手札と公開情報のみであり、不完全情報モードのまま比較する。

シードは戦略名・バージョンごとに独立した乱数源へ変換する。登録設定と内部状態が同じで、戦略が再現可能な乱数源を使う場合は、時間を除いて判断を再現できる。局面や比較対象を変更すると古い結果は消える。

詳細なAPI・内部状態の扱い・制限は [同一局面比較の設計](docs/position-comparison.md) を参照。局面エディタ・比較結果の保存と読み込みUIは未実装。分岐シミュレーションは下記の手順で利用できる。

## Windowsでの初回セットアップ

Windows PowerShell 5.1以降で、リポジトリのルートから実行する。管理者権限は不要。

1. [Node.js公式サイト](https://nodejs.org/)から22.12以降のLTSを導入する。導入後はPowerShellを開き直し、`node --version` と `npm --version` を確認する。
2. pnpmがなければ `npm install --global pnpm@11.25.0` を実行する。`pnpm --version` が11系であることを確認する。
3. 次のセットアップスクリプトを実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

uvが未導入なら、[uv公式のWindows推奨手順](https://docs.astral.sh/uv/getting-started/installation/)でユーザー環境に導入する。Node.js・pnpmのバージョン確認、`backend` での `uv sync --locked`、`frontend` での `pnpm install --frozen-lockfile` を順に行う。Python 3.12以降が見つからない場合はuvが取得するため、Pythonを別途手動インストールする必要はない。

uvだけを手動導入する場合:

```powershell
powershell.exe -ExecutionPolicy Bypass -Command "irm https://astral.sh/uv/install.ps1 | iex"
```

導入後、新しくPowerShellを開いて確認する。

```powershell
uv --version
```

既に開いていたPowerShellで認識されない場合は、現在のセッションにだけ追加できる。

```powershell
$uvBin = Join-Path $env:USERPROFILE '.local\bin'
if (-not (($env:Path -split ';') -contains $uvBin)) {
    $env:Path = "$uvBin;$env:Path"
}
uv --version
```

公式インストーラーは既存のユーザーPATHを保持してuvの配置先を追加する。上記のコマンドと開発スクリプトは、既存PATH全体の置き換えやシステムPATHの変更をしない。ターミナル自体が古い環境を保持している場合は、Windows TerminalやVS Codeも起動し直す。

`-ExecutionPolicy Bypass` はそのプロセスだけに適用され、PC全体の実行ポリシーは変更しない。スクリプトは日本語をWindows PowerShell 5.1で読めるようUTF-8 BOM付きで保存している。

## Windowsでの一括起動

初回セットアップ後は、次の1コマンドで両サーバーを起動できる。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

- uv・Node.js・pnpm、セットアップ済みファイル、依存定義の変更、Python依存の整合性を確認する。不足時は `setup.ps1` の再実行を案内する。
- バックエンドは `127.0.0.1:8000`、フロントエンドは `127.0.0.1:5173` で起動する。両方の応答を確認してから既定のブラウザでゲーム画面を開く。
- 8000または5173が使用中なら、ポートと取得可能なPIDを表示して起動を中止する。既存のプロセスは停止せず、別ポートにも自動移動しない。
- 両サーバーのログを同じPowerShellに `[backend]` / `[frontend]` 付きで表示する。ログファイルは `.dev-state/logs/実行日時/` に保存する。
- **Ctrl+Cで両サーバーを終了する。** Windows Job Objectで今回起動したプロセスとその子だけを管理し、途中の起動失敗や片方の異常終了時も停止する。専用PowerShellプロセスの終了時にも子プロセスを終了する。

ブラウザを自動で開かない場合:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -NoBrowser
```

起動確認後に指定秒数で停止する検証用オプションもある。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -NoBrowser -StopAfterSeconds 5
```

ヘルスチェック:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
# status: ok
```

依存ファイルを更新した場合や `node_modules` / `.venv` を削除した場合は、先に `setup.ps1` を再実行する。スクリプトは呼び出し元のカレントディレクトリに依存せず、リポジトリ内の各ディレクトリを使う。

### 同じ局面から分岐シミュレーション

「同じ局面でAIを比較」から現在・履歴の局面を選び、比較後の候補カードを起点に残りのゲームを試せます。候補は手札から追加・解除でき、各席の継続戦略、試行回数、シードを指定できます。推定勝率と95%信頼区間、平均最終得点、順位分布、ばらつき、候補間の対応差を確認できます。

不完全情報の一様サンプリングを利用し、実対戦の隠れた手札は推定評価に使いません。継続戦略は登録初期状態から開始します。計算中は進捗を表示し、停止できます（1件ずつ、1〜1000試行、候補数×試行数は10000以下、制限60秒）。推定はサンプリングと継続戦略の仮定に依存します。詳細は [分岐シミュレーションの設計](docs/branch-simulation.md) を参照してください。

### ゲームルールを確認する

上部ナビゲーションの「ゲームルール」から、配札・カードの強弱・3段階の得点計算・同点・公開範囲を確認できます。数字を優先し、同じ数字は **♠ > ♥ > ♦ > ♣** で比較します。この順序は公開二次資料により採用し、2026-10-13の監査で2003年・2021年研究論文本文でも確認しました。竹内氏の正式原典全文の確認済みとは扱いません。

エンジンで計算した具体例のほか、3枚を選んで判定するサンプルも利用できます。確認状況と根拠は各項目から展開できます。詳しい仕様は[現在採用しているルール](docs/current-rules.md)、調査経緯は[ルール調査](docs/rules-research.md)を参照してください。既存の対戦状態や実験設定は変更しません。

### ルール監査で分かった得点の区別

[ルール整合性監査](docs/rules-audit.md)で資料・実装・検証結果を照合した。現行の平均得点は5ラウンド獲得点の合計で、2003年研究論文にある勝敗確定後の別報酬（単独勝者+2、2人勝者各+1、全員勝者0等）ではない。勝者判定を維持し、この別報酬を独立フィールドとして実装した。原案での必須性は未確認であり、今回ゲームの挙動は変更していない。勝率と期待報酬は異なる評価目的なので混同しない。

今回の文書更新理由は、研究本文取得による根拠状態の更新と、実装済みの分岐シミュレーションを未実装とした古い案内の訂正である。その後、終局報酬の実装とアプリ内説明を追加した。Windowsセットアップ・起動手順は維持した。

### 終局報酬で戦略を比較する

終局結果に最終累計得点・勝者・単独/共同勝利と3人の終局報酬を表示します。報酬は単独勝者+2/敗者各−1、2人勝者各+1/敗者−2、全員勝者0。累計へ加算せず、勝者を再判定しません。

比較実験・アルゴリズム図鑑に単独/共同勝利率、平均累計得点、平均終局報酬を追加しました。実験グラフは平均累計得点と平均終局報酬を切り替えられます。分岐結果でもこれらを確認でき、詳細には共通試行に基づく報酬差と近似95%区間を表示します。戦略の判断ロジックは変更していません。

SQLiteの旧結果は有効な勝者情報から読み取り時に補完し、元データを変更しません。不明を0にせず、記録済み・補完・不明の件数を区別します。ルール版は維持し、報酬版saichugen-2003-table2-v1を別に記録します。詳細は[終局報酬と評価指標](docs/terminal-rewards.md)。


### Monte Carlo Rollout（Phase 16）

戦略選択欄の `monte_carlo_rollout` は、各合法手から仮想対局を行い、**期待終局報酬**が最大のカードを選びます。通常対局・人間対AI・AI観戦・比較実験・図鑑・同一局面比較で利用できます。既定は候補ごと8試行、全席Random継続です。相手の実手札を参照せず、本人の観測から一様に手札候補を作り、候補間で世界と初期乱数を共有します。

判断詳細では候補評価・補助指標・近似95%区間・探索seed・時間・最善/次点の差を確認できます。時間上限等の詳細設定はPythonコンストラクタまたは設定付きfactory登録で指定します。設定方法・サンプリングの限界・性能測定・参考対戦結果は[Phase 16](docs/phase16.md)。少数試行の推定であり、MCTSや最適性の保証ではありません。Windows起動手順は従来どおりです。


### Rolloutの探索品質評価（Phase 17）

「探索品質」タブで、A：8/16/32/64試行（Random継続）、B：8試行のRandom/Greedy/ScoreAware継続を比較できます。見積もり後に実行し、進捗・中断、SQLite履歴、設定/結果JSON、平均終局報酬と配札単位95%区間、計算時間の散布図、対応配札の基準差、同一局面の選択変化を確認できます。まず小規模に時間を測り、独立配札を段階的に追加してください。詳細・CLI再現手順・小規模実測・限界は[Phase 17](docs/phase17.md)。Phase 16の基準コミットは8b380bec5e85f6368f7aa2f1c49db818f3abb160です。

### 探索評価の信頼性（Phase 18）

Phase 18のStage 1（2配札・8/16試行）はプリセットから選択できます。相手構成別の小規模プリセットと、混合相手10配札のStage 2を追加しました。実行前に時間・JSON容量を概算できます。全6席順が正しい条件で揃った配札だけを統計に使い、10配札未満・標本分散0では区間を表示しません。10〜19配札の区間も参考値です。

保存実験同士は、相手・seed・基準SHA・ルール・情報条件・実装等を照合し、条件の一致する共通配札だけを対応比較します。条件が異なる場合は理由を示して拒否します。実測では10配札・120対局で16−8試行の報酬差+0.067、参考95%区間−0.450〜+0.583となり、改善を確認できませんでした。設計・再現方法・性能・制限は[Phase 18](docs/phase18.md)。Windowsセットアップ・通常起動方法は変更していません。

### Hybrid Search Lab（Phase 19）

総予算64の4戦略 `budget_rollout`（均等）、`hybrid_heuristic`（Heuristic優先）、`hybrid_adaptive`（UCB型配分）、`hybrid_combined`（組み合わせ）を対局・観戦・同一局面比較・図鑑・一括実験で選べます。全候補を最低評価し、残り予算の配分を変えます。最終選択は期待終局報酬だけで、Heuristic点は加算しません。従来の `monte_carlo_rollout` は維持しています。

「探索品質」はHybrid Labとしても利用できます。既定プリセットは1配札・総予算32の4方式比較。見積もり後に実行し、配分・判断時間・独立配札数・対応報酬差を確認できます。判断詳細では候補別配分グラフと予算消費を表示します。総予算が異なる実験は対応比較しません。予算不足時は探索せず合法手に退避し、時間上限・未使用予算も記録します。

32/64/128の予備比較は各2配札で、改善や相乗効果を断定できません。候補の適応配分には選択バイアスがあり、候補区間は未提供です。設計・設定JSON・測定結果・制限は[Phase 19](docs/phase19.md)。通常起動は従来どおり `powershell.exe -ExecutionPolicy Bypass -File .\scripts\dev.ps1` です。

### Theory Lab（Phase 20）

「Theory Lab」で6つの未検証仮説（強い札／中程度の札の温存、ラウンド重視、累計逆算、公開記憶、相手目標推定）を個別に設定できます。仮説の前提・代理評価式・制限を確認し、オン/オフ、重み、パラメータを編集してください。人工局面の単独寄与・組み合わせを表示し、仮説なし対照・単独・組み合わせ・比較戦略の実験計画を生成できます。計画作成だけでは実行しません。

既存の見積もり・進捗・中断・SQLite履歴・JSON保存・配札単位統計を再利用しています。直接評価の点数は期待終局報酬ではありません。`theory_policy`、`theory_search`、`theory_search_adaptive` は通常の対局・観戦・比較・図鑑でも選べます。探索版はTheory点を配分にだけ使い、最終選択は終局報酬平均です。直接選択の同点は既定でseed付き乱択にして、仮説なし対照が低い札を暗黙に温存する偏りを避けます。

新しいTheory実験では開発・検証・最終評価のseed用途を指定し、区分の範囲混入を拒否します。予備比較は各2配札で、強さや相乗効果を示すものではありません。評価器・実測・保存形式・過学習対策・次フェーズの境界案は[Phase 20](docs/phase20.md)。Windowsのセットアップ・起動方法は変更していません。

### Codex Strategy Arena（Phase 21）

「Strategy Arena」で、Codexが考案した5つの未検証候補（選択肢温存・現在ラウンド・累計逆算・公開得点から相手目標を仮定・局面で重み切替）を比較できます。各候補と相手2役の構成を指定し、共通配札・全6役割順で対戦します。同じ戦略を複数席へ置くこともできます。見積もり後に実行し、進捗・停止・SQLite履歴・JSON保存、報酬・単独/共同勝利・敗北・計算時間・席別成績・条件の一致する対応報酬差を確認してください。

戦略詳細には仮説・設定・版・hash・親と派生版・過去実験を表示します。派生JSONを編集して別版を登録できます。任意コードや式は受け付けず、既存Theoryと探索方式の許可された設定だけを使用します。初期5候補は通常対局・観戦・図鑑でも選べます。追加登録したカスタム版はArena内で版を指定して利用します。

評価配札seedと戦略の方策rngは分離しています。独立配札10件未満では区間を表示せず、少数実測を強さの証明にしません。小規模プリセット・CLI再現方法・5候補全体の結果・保護の範囲・制限は[Phase 21](docs/phase21.md)。自動進化や自動採用はありません。初回は `powershell.exe -ExecutionPolicy Bypass -File .\scripts\setup.ps1`、通常起動は `powershell.exe -ExecutionPolicy Bypass -File .\scripts\dev.ps1` を引き続き使用します。

### Strategy Evolution（Phase 22）

「Strategy Evolution」で親戦略から重み・局面規則・探索設定の子候補を生成し、登録、実験計画の固定、開発評価、明示選抜、検証、最終評価、採用を別操作で行えます。生成専用seedと評価用seedは分離し、親・既存版を上書きしません。系譜、設定差分、段階別の報酬・対応差・判断時間、採用状態、保存履歴とJSONを確認できます。Codexへの改善提案用JSONは開発集計だけを出力し、任意コードや外部LLM APIは使いません。

少数配札では自動採用せず、採用には固定した基準、検証・最終評価の通過、ユーザーの理由付き操作が必要です。Evolutionでは最終seedの予約・既存使用を確認して再利用を拒否します。今回の温存系・局面切替系の小規模比較はいずれも証拠不足・保留で、改善を断定していません。事前仮説、全結果、CLI再現方法、統計と運用の制限は[Phase 22](docs/phase22.md)。Windowsのセットアップ・通常起動方法は変更していません。

### Evaluation Lab（Phase 23）

「Evaluation Lab」で強さ・信頼性・頑健性・汎化・効率を分けて確認できます。共通配札の対応差、複数相手構成・席順別の成績、計算時間、必要配札数の設計概算、次の実験条件を表示します。相手別結果は既定で統合せず、事前重みがある場合だけ混合条件の対応差を集計します。

温存系・局面切替系の2×2 Ablation、Evolutionの固定親子取込、見積もり、進捗・中断・SQLite履歴・JSON保存に対応します。2配札・分散0では精密な必要数を出しません。正式な判定は固定標本の有界区間と多重比較補正で、逐次判定や最終評価seedの実行は行いません。新しいEvolution実験にも固定標本補正を追加し、旧保存実験は旧方式として維持します。

今回の各構成2配札のパイロットは全件判定保留です。式・仮定・実測・再現方法・制限は[Phase 23](docs/phase23.md)。推薦を計画欄へコピーしても自動実行しません。既存Windows起動手順は変更していません。

### Experimental Design Lab（Phase 24）

仮説・戦略版・共通配札・相手構成・比較family・計算予算を、実行前に固定する画面です。Draft保存→事前登録→Hash付き実行を分離し、進捗、停止、JSON保存、次の設計案を確認できます。構成間の効果差も独立配札単位で比較します。推薦はDraftのみ生成し、自動実行しません。詳細と小規模追試は[docs/phase24.md](docs/phase24.md)を参照してください。既存のWindows setup.ps1／dev.ps1の利用方法は変わりません。

### Evidence Accumulation Lab（Phase 25）

完了PlanをEvidence Seriesへ関連付け、追加独立配札による平均報酬差・ばらつき・計算時間の変化を確認できます。実配札の重複と条件不一致を拒否し、構成別の収束グラフ、追加予算見積もり、次のDraft提案を表示します。途中区間は探索的な診断であり、逐次的な採用・棄却を保証しません。使い方と実測は[docs/phase25.md](docs/phase25.md)を参照してください。既存のWindows起動手順は維持しています。

### Zigzag Strategy Lab（Phase 26）

Zigzag（強→弱）とReverse Zigzag（弱→強）を通常対局・観戦・比較・実験で選択できます。専用Labでは事前登録してカード消費、序盤・中盤・終盤のターン順位、ラウンドと累積順位、単独2位・同点・終局報酬を比較します。中央札が残ることは勝利を保証しません。詳細は[docs/phase26.md](docs/phase26.md)を参照してください。Windowsのsetup.ps1／dev.ps1の手順は維持しています。
