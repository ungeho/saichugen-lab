# 同一局面でのアルゴリズム比較

## 既存機能の再利用

ゲームの進行・得点・合法手は既存エンジンを利用する。選択直前の局面は `research.replay.export_full` の複製データの行動列を途中までにし、既存replayで検証・復元する。完全状態は復元エンジンの中だけで扱い、各戦略には `Game.observe(player)` の同一インスタンスだけを渡す。

戦略は既存の登録機能から取得し、`decide(..., capture_details=True)` と `decision_record` を利用する。図鑑情報は既存APIから再利用し、判断の詳細表はDecisionExplanationコンポーネントを対戦履歴と比較画面で共有する。比較をバッチ対戦経路には組み込まない。

## 局面と観測

ターン番号はAPI内では0〜14、画面では1〜15。指定番号の**選択直前**を復元する。現在局面なら未実行の次の選択、履歴を選べば表示したターンの選択直前。終了後の現在表示は最後の選択直前を使う。

局面データは次のJSON形式。

| 項目 | 内容 |
| --- | --- |
| schema_version | 観測形式のバージョン（現在1） |
| rule_version | 実際のルール識別子 |
| information_condition | 現在はimperfectのみ |
| observation | 対象者の手札、ターン、得点、残り枚数、それ以前の公開履歴 |
| legal_actions | その局面の合法手 |
| snapshot_id | 観測・ルール・情報条件の標準化JSONをSHA-256で識別 |
| game_reference | 現在のセッションのゲームID、ターン、対象者 |

snapshot_idは**観測内容**の識別子で、非公開手札・内部モデル状態の識別子ではない。同じ観測IDでも、戦略の内部状態や設定が違えば判断は変わりうる。

公開JSONに配札シード、相手の非公開手札、余り札、完全状態の参照を含めない。終了後に他プレイヤー視点を開く場合も、各戦略にはその対象者の通常の不完全情報だけを渡す。他の席で活動した戦略の私的な内部状態を、対象者の比較へ流用しない。

## API

- `GET /api/games/{id}/comparison-position?turn=0&player=0&analysis=false`
- `POST /api/games/{id}/compare`

比較リクエスト例:

```json
{
  "strategies": ["Random", "Greedy", "Conservative", "ScoreAware", "Heuristic"],
  "seed": 42,
  "turn": 0,
  "player": 0,
  "analysis": false,
  "information_condition": "imperfect"
}
```

応答はposition、比較シード、結果配列、乱数の説明。結果には名前・実バージョン・状態の出所・独立シード・Decision記録・判断時間・成功またはエラーを含む。戦略リストは重複不可で1〜32件。比較シードはブラウザが正確に扱える整数の範囲とする。

未到達や終了後の選択不能局面は409。他プレイヤーの視点はゲーム終了後かつanalysis=trueの場合のみ取得でき、それ以外は403。未登録戦略、重複、未対応の情報条件は422。

## 内部状態の維持と隔離

| 状態の出所 | 扱い |
| --- | --- |
| live_copy | 対象席で現在動いている同名戦略の実インスタンスを複製 |
| history_reconstructed | 対象席の保存した初期インスタンスから、元の乱数状態と実際の履歴で当時まで再実行 |
| registered_initial_copy | 対象席で動いていなかった戦略は、登録factoryが返す設定・学習済み値を持つ初期インスタンスを複製 |

対象席に存在しなかった戦略について、当時の内部状態が存在したかのようには扱わない。別の席の同名戦略をコピーすると、その席で知った私的情報まで混ざるため流用しない。結果の状態欄で差を確認できる。

ゲーム開始時に対戦用インスタンスとは別の初期コピーと乱数状態を保持する。人間が操作したP1のターンでは、元の対戦も戦略chooseを呼んでいないため、履歴再実行でも呼ばない。再実行の選択と記録が一致しない場合は、復元不能として報告し、現在状態や新規インスタンスで代用しない。

通常はdeepcopyを使う。コピーが難しいリソースを持つ戦略は、任意の `clone_for_comparison()` で独立したインスタンスを返せる。設定・学習済み値・必要な内部状態を維持し、元の可変状態を共有・変更しないこと。元インスタンスそのものを返す実装は拒否する。複製未対応でも通常対戦は開始できるが、その戦略の比較はエラーとして案内する。

状態の複製や履歴再実行は比較用だけに適用し、対戦のGame、戦略、rngを変更しない。比較戦略が返したカードも対戦へ適用しない。合法手外のカードはエラーにする。一つの戦略が失敗しても、他の結果を返す。

## ランダム性・時間・表示

各戦略の比較用rngは、指定シード・名前・実バージョンから既存derived_seedで作る。選択順序を変えても同じ戦略の乱数系列は変わらず、通常対戦のrngにも触れない。派生シードは大きな整数をブラウザで丸めないよう文字列で返す。

履歴の過去部分には元の対戦rngを使い、比較対象となる最終の1手だけは比較シードで再判断する。したがってRandomなどは実際の対戦で出した札と違うことがある。

時間は比較用乱数源を作った後、戦略の判断呼び出しを計測する。局面復元・複製・シリアライズの時間は含めず、再現性の対象外とする。どの戦略も同じ観測を受けるが、内部の乱数の使い方や学習済み値まで同じにするものではない。

選択カードが一致した結果をグループ化し、各戦略の概要と、開いて読む候補評価・計算内訳を分ける。評価値の尺度は既存戦略の説明をそのまま用い、戦略間の大小を強さの順位にしない。理由・候補評価の未提供を明示し、架空の値は補わない。

局面切り替え・対戦進行時は古い比較結果を消し、遅れて届いた旧局面の応答も新しい局面に表示しない。

## 制限と今後の拡張

- 不完全情報のみ対応。将来の完全情報・カスタム条件は、局面生成とAPIの許可条件を拡張し、条件識別子を分ける。
- 初期状態のコピーはゲームセッションのメモリ上に保持する。大きな学習モデルではコピーに時間・メモリが必要で、読み取り専用モデルを共有する専用cloneメソッドなどが拡張候補。
- 再現性は渡されたrngや複製可能な内部乱数に従う戦略が対象。時刻・グローバル乱数・外部サービス・外部への書き込みを利用する戦略の再現や副作用までは一般的に保証できない。cloneメソッド自体も元状態を変更しない契約とする。
- 歴史的な内部状態は履歴再実行による復元で、全ターンのモデルチェックポイントを保存する仕組みではない。高度な戦略向けのチェックポイント方式は今後追加できる。
- 比較は同期処理。現在の対戦APIのロック内で復元・複製・判断するため、時間のかかる探索モデルでは通常操作の応答も待つ場合がある。この一手の判断比較は同期のまま。別機能の分岐シミュレーションはバックグラウンド実行・停止・時間制限に対応する。
- 比較結果のSQLite保存・読み込み、観測JSONを直接入力するAPI、局面エディタは未実装。API応答は観測と再現条件を持つが、モデル状態や非公開ゲーム全体を保存した形式ではない。セッション再起動後にgame_referenceから完全状態を復元することはできない。
- 分岐シミュレーションを追加済み。観測だけから隠れた手札をサンプリングして分岐し、実対戦の隠れた手札は評価に流用しない。詳細は[分岐シミュレーション](branch-simulation.md)を参照。
