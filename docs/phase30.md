# Phase 30：Decision Reliability Lab

## 目的と基準版

有限Rolloutの札選択が、予算、選択時の乱数、継続戦略の仮定にどれだけ依存するかを調べる。選択誤差、モデル不一致、小さな真の価値差は競合する説明だが、同時に成立し得る。今回だけで原因を識別したとは扱わない。

Phase 29は `29cd1e46906ef84ae6e93767c3998181f3c1b719`、メッセージ「中間順位の意思決定規則と独立評価を追加」で通常commit・push済み。前回監査時の15ファイルのSHA-256一致と公開対象・リモートmainを確認し、成功済み検証の全件再実行は省いた。force pushは使用していない。Phase 30は未ステージ・未commit・未push。

[Phase 29](phase29.md)の4配札・12局面・1376派生対局、一致1/12、Self/Terminal不一致10/12、Terminal劣後診断6局面、配札等重み報酬Self +0.4271／Gap +0.2474／Safety +0.3281／Terminal +0.2917は過去の探索結果として保持する。新実験と合算しない。既存19実験行を新しいローカルDBへバックアップし、実験後もpayload SHA-256一致を確認した。

## 診断集団と新規集団

`diagnostic_source_id`に完了したPhase 29実験を指定すると、Terminal劣後フラグがある局面を記録順で上限件数だけ選ぶ。元snapshot・config・結果Hash、観測Hashを確認し、本人の観測から合法世界を復元して公開履歴の整合性を検査する。登録時に観測・配札Hash・局面Hash・元条件Hash・元結果Hashを凍結する。

## 予算感度と共通サンプル

予算は16・32・64・128・256から昇順・重複なしで登録する。同一モデル・反復内では最大予算まで一度だけサンプルを生成し、各予算はその先頭を使用する。予算間は独立ではない。全合法手、観測、報酬、継続設定を固定する。

各prefixで全候補の期待報酬・標本標準偏差・直近2位率などを保存し、Phase 29の4規則で選ぶ。同点はランク昇順・同ランクはスート昇順。Terminalの上位2候補の平均報酬差と対応区間、登録した予算チェックポイント間の札変更回数、最大予算との一致、prefix時点の累積時間を記録する。最大予算札は真の最適手ではない。

実計算量は `合法手数 × 最大予算 × 反復数 × 選択モデル数`。16+32+64+128+256を足し算しない。モデルは異なる政策で対局を進めるため、モデル間の対局は実際に計算する。

## 選択乱数の感度

反復ごとに独立した選択seedを導出する。モデル間では同じ世界seed・試行番号を使い、同じ隠し札世界で比較する。政策乱数にはモデル名・版が入り、異なる政策間の乱数消費まで一致する保証はない。候補札間では既存rolloutの席別乱数状態を共有する。

予算・モデル別にカード選択頻度、最頻割合、エントロピー（bits）、異なる反復の札不一致率、候補評価値の反復間標準偏差を保存する。不一致率は `1 − Σ n_c(n_c−1)/(R(R−1))`。R<2なら未算出。

カード別頻度には既存Wilson関数の周辺95%区間を付ける。カード間の多重補正はしておらず、最頻札を選んだ後の同時信頼区間ではない。2反復で一致しても、選択の正しさや安定予算を確証しない。

## 独立評価とモデル交差

選択とは別の世界seedで、各評価モデルの**全合法手**を評価する。選択モデルと評価モデルはRandom、Heuristic、ScoreAwareを交差させ、各モデルは全席の継続仮定として使用する。モデル内は対角、モデル外は非対角。評価モデル列を無条件に平均しない。

評価世界はモデル間で共有し、政策は各モデル自身の観測だけを使う。評価表は予算・選択反復間でも共有するため、反復数を独立評価世界数へ掛けない。固定された札についてTerminal−Self、Terminal−最大予算札を同じ評価試行の差から計算する。同じ札なら差は恒等的に0で、異なる札の観測差0では区間を0に縮めない。

モデル依存の診断では、あるモデルで選んだ札と別モデルで選んだ札を、各評価モデル内で対応比較する。「自モデル評価では高く、別モデル評価では低い」という点推定の反転も保存する。相手の実際の戦略を正しく推定できたことを意味しない。

## Optimismと探索的Regret

`selection_optimism = 選択時の推定報酬 − 独立評価報酬`。同じ選択・評価モデルのときだけ定義し、モデル外ではnullにする。正の観測値だけでWinner’s Curseを証明したとは扱わない。複数独立配札での傾向が必要。

有限標本の参照札は各評価モデルの独立評価表で報酬最大の札。同点処理は固定カード順。各4規則について `estimated_regret = 参照推定値 − 選択札推定値` を保存する。

同じ評価標本で参照札を最大値選択するため、Regretには上方バイアスがあり得る。参照選択と測定の第三標本分離は今回未実装で、すべて**探索的Regret**。真の最適手に対する損失や確証指標として使用しない。

## 層別と統計の単位

厳密中間・最高・最低・同点、均衡・上側接近・下側接近、両側小差・大差、時間区分はPhase 28・29を再利用する。合法手数、残りラウンド数、直近自己2位率の最大推定値、上位2候補の推定差、Self/Terminalの選択一致も分類する。

追加分類版は `reliability-bins-v1`。直近最大率は[0,.25)、[.25,.5)、[.5,.75)、[.75,1]。上位推定差は.1未満／.1以上.5未満／.5以上。閾値は登録前に固定し、推定値で層別するため探索的な分類として扱う。

集計は同じ集団・選択モデル・予算・評価モデル・層内で反復→局面→配札の順に平均する。各層の独立配札数を記録し、同一配札の複数局面を独立に数えない。異なる評価モデル・診断/新規集団・過去実験を統合しない。

候補値と対応差は既存の固定標本Hoeffding境界＋Bonferroni。選択family上限は `局面上限×モデル数×反復数×予算数×(17+272)`、評価は `局面上限×モデル数×17×17`。評価表を共有するので、その全札対比が各選択の対比を覆う。報酬は絶対上限2、差は4。配札集約の補正familyは10000。配札10件未満では既存関数が区間を返さず、今回は配札単位の区間を提供しない。候補・対応差の世界単位区間とは区別する。

## 使用方法・保存・再現

「Decision Reliability Lab」で診断元を選ぶか、新規局面のみで、見積もり→登録→条件Hash付き実行を行う。予算・反復・モデルを切り替え、選択表、分布、モデル行列、optimism・Regret、公開観測、層別集計を確認する。SQLite履歴・JSON保存・停止・Draft・Evidence参照に対応する。参照だけを保存し、異なる世界や集団をEvidenceの独立配札差へ合算しない。

APIは `/api/reliability/estimate`、`/jobs`、`/jobs/{id}`、`/export`、`/start`、`/cancel`、`/design-draft`、`/evidence`。kindは `decision_reliability_v1`。snapshot・結果Hashを検査し、改変した結果はInvalidatedとして隠す。登録だけでは実行しない。

CLIはリポジトリ直下から実行する。

```powershell
$env:PYTHONPATH = 'backend/src'
# 新規局面のみ。通常は見積もりだけ
backend/.venv/Scripts/python.exe -m strategy_arena.experiments.reliability_cli --config experiments/presets/reliability-pilot.json
# 診断元があるDBでは、設定JSONのdiagnostic_source_idへ元IDを指定
backend/.venv/Scripts/python.exe -m strategy_arena.experiments.reliability_cli --config research-local/my-config.json --database research-local/my-reliability.sqlite --register --output research-local/registered.json
backend/.venv/Scripts/python.exe -m strategy_arena.experiments.reliability_cli --config research-local/my-config.json --database research-local/my-reliability.sqlite --run <実験ID> --output research-local/result.json
```

今回の実測は `research-local/phase30/pilot-config.json` と `results.sqlite`。同じIDの元Phase 29結果を含む保管DBで再現する。既定開発DBとは別なのでCLI実測が通常画面へ自動的に混ざることはない。公開プリセットの診断元はnullであり、利用者のDB内の完了Phase 29結果を別途選ぶ。

同じ局面・条件・版・seedなら計時以外の結果を再現する設計。選択反復と評価を別名前空間で導出し、最終評価seedは使用しない。新規配札・評価系列の予約が衝突する再登録は拒否する。バックアップ上で同じ世界を再計算しても独立証拠を増やしたとは数えない。

## 制限と次の課題

- 各集団1配札、選択2反復、評価64世界なので一般化・原因の識別はできない。診断元の結果選抜バイアスを残したまま新規集団と統合しない。
- 最大予算までの一致や2反復での一致は正しさの証明ではない。推定報酬・真の価値差の区別が必要。
- モデル間の政策乱数はモデル名・版を含み、完全な乱数消費対応を強制しない。共通世界の効果も有限。
- 評価表を予算・反復間で共有するため、その数だけ評価標本が増えたとは扱わない。
- Regretの参照選択と測定は未分離。第三の世界標本を使う追試が必要。
- 相手政策の推定、カード温存の因果効果、ケースBの機序は未検証。
