## 4方式と総予算

従来の `monte_carlo_rollout` は候補ごとの試行数を指定する。これを維持したまま、意思決定全体のRollout上限を持つ別戦略を登録した。

| 方式 | 登録名 | 最低評価後の追加配分 |
| --- | --- | --- |
| Baseline | `budget_rollout` | 評価回数の最少候補へ順番に配分。端数はカード順 |
| Hybrid A | `hybrid_heuristic` | Heuristic上位 `ceil(候補数/4)` 枚に均等配分 |
| Hybrid B | `hybrid_adaptive` | 実測報酬平均と試行数から求めたUCB型の配分値が最大の候補 |
| Hybrid C | `hybrid_combined` | Bの配分値に、試行数とともに弱まるHeuristic順位の優先項を加える |

全方式の最終選択は **候補の終局報酬標本平均の最大化**。Heuristic点、UCB値、勝率、累計得点を最終選択スコアへ加算しない。同じ平均なら数字・スートのカード順で先頭。合法手数×試行数で総予算が増える比較を避ける。

既定は総予算64、最低1試行、全席Random継続、時間上限なし。最大予算1024、最低試行は1〜8。通常対局・観戦・同一局面比較・一括実験・図鑑で登録戦略を利用できる。詳細設定はPythonコンストラクタまたは探索品質画面のJSONで指定する。

```python
from strategy_arena.strategies.hybrid import HybridSearch

strategy = HybridSearch(method="combined", total_budget=64, min_trials=1,
                        continuation="Random", seed=42, time_limit_ms=None)
```

合法手が1枚なら探索しない。予算が `合法手数×min_trials` に満たない場合も探索を行わず、全候補を未評価としてカード順の合法手へ退避する。部分的にしか評価していない候補を、全候補比較の勝者として扱わない。

時間上限は協調方式（0〜5000ms）。全候補の最低評価が揃う前なら合法手へ退避し、揃った後なら採用済み報酬平均を使用する。初期評価の中断した一巡は採用しない。開始数・終局まで実行した数・評価採用数・未使用予算を分ける。途中で停止した仮想対局も開始数として予算を消費し、開始数が総予算を超えない。

## 配分アルゴリズム

Heuristicアダプターは既存 `Baseline("Heuristic").choose_detailed()` の候補評価値をそのまま読む。獲得方針、目標得点からの予想距離、残す札の項を再実装しない。既存戦略は変更せず、評価同点の優先順位だけカード順に固定する。Aは全候補を最低評価した後、上位4分の1へ残りを回すため、上位でない候補の推定が粗いまま残る弱点がある。

Bの配分値は `報酬平均 + 4*sqrt(2*log(全採用数+1)/候補採用数)`。報酬範囲−2〜+2に合わせた楽観項で、少数評価の候補を再訪する。これは実装上のUCB型の配分規則であり、候補間が相関する共通サンプル・有限予算条件での理論保証や95%区間を意味しない。候補を永久除外するSuccessive Halvingは採用しなかった。

Cはこの値へ `順位優先度/(候補採用数+1)` を加える。順位優先度はHeuristic最上位1、最下位0の順位で、Heuristicの生の点数の正規化ではない。配分にだけ使い、追加試行が増えると影響を弱める。定数や上位割合の最適性は未検証。

## 再利用と不完全情報

- 仮想対局は既存 `rollouts.rollout_trial` を利用。分岐シミュレーションや探索戦略を再帰呼び出ししない。
- `sampled_game` と `UniformSampler` が本人の観測から未知札を配分し、公開履歴を再現する。実際の相手手札・余り札は渡さない。
- 継続戦略は軽量5戦略に限定。全席の登録初期状態を各候補・試行に複製し、自分自身の観測だけを渡す。
- 戦略レジストリ・図鑑の説明モデル・判断詳細・QualityJobs・SQLite・配札単位集計を再利用した。

一様サンプラーは枚数・カード重複・公開履歴を維持するが、相手の過去行動の尤度による重み付けはしない。完全な情報集合の事後分布とは主張しない。

## 乱数・共通条件

探索seedは対局rngから128bit取得するか、固定整数を指定する。手札・合法手をカード順へ揃え、表示順による結果変化を防ぐ。候補の `k` 回目には既存の `branch-world:k`、席別 `branch-policy:k` から生成した世界と初期乱数を使う。同じseed・観測・継続戦略で同じ試行番号を実行した候補・方式間は共通条件になる。

適応型では候補ごとの実行回数が違うため、全候補に同じ標本集合があるとは限らない。候補が多く評価される理由自体が過去の観測結果に依存し、標本平均には選択バイアスがあり得る。候補の95%区間は全4方式とも未提供とする。対局を通じた成績の配札単位区間とは別物。

追加試行は共通関数を1候補ずつ呼ぶため、同じtrial番号の世界を再構築することがある。結果は一致するが再サンプル・履歴再現の時間がかかる。従来方式と同じ回数でも時間が同じとは限らない。時間上限なしの再現性と、時間上限ありの実行環境依存を区別する。

## 実測結果

CPU：Intel Core Ultra 7 265K、20コア/20論理。Python 3.12.14。相手はRandom/Heuristic、全席Random継続、最低1試行、時間上限なし、方策seed42。各配札に全6役割順を使う。設定間で配札と役割別初期乱数を共有する。

Stage 1はseed0の1独立配札、総予算32、4方式×6席順の24対局。見積もり5.84秒に対して実測5.27秒。方式ごと2880 Rolloutで一致し、対局が終局し保存・集計できることを確認した。

人工の共通局面プローブ1件では、予算32/128は全方式が♥Kで一致（6ペア中6）。予算64ではAが♥K、他3方式が♠8（6ペア中3、一致率50%）。候補5枚への採用配分は均等 `[13,13,13,13,12]`、A `[1,1,31,30,1]`、B `[15,15,9,13,12]`、C `[14,14,10,13,13]`。これは対戦中の一般的な一致率ではなく、同じ配札で先頭合法手を12回出した局面1件の比較。

## 制限と次の改善

候補平均の選択バイアス、UCB係数・Heuristic優先割合・最低試行数の調整、2配札という小標本が主な制限。相手構成も混合1種類のみ。十分な独立配札での追試、別の相手構成、実対戦中の同一観測スナップショット収集は未実施。Stage 2の結果から優勝設定や最適な既定値を選ばない。次は少数設定を固定した10〜20配札の計画を見積もり、別の独立seedで追試する。

Bayesian Samplingは未実装。将来は共通の `sampled_game`／`UniformSampler` 境界に観測を受け取る別サンプラーを導入し、行動履歴の尤度、Opponent Modeling、推定校正を実装する案がある。一様版と別のサンプラーID・バージョン・設定を結果に保存して比較し、通常Strategyには実手札を渡さない。今回、根拠のない事後確率や新しい確率モデルは追加していない。
