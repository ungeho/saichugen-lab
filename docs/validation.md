2026-10-13、Windows、Python 3.12.14、Node.js環境で検証。

## 結果

- pytest: 27件成功。カード全3枚組合せ、配札保存則、同点、得点各層、15ターン進行、違法操作の非破壊性、完全リプレイ、観測分離、未知札・候補サンプリング、5戦略、登録戦略、API、SQLite再取得、Brier評価、既知データ集計を確認。
- Vitest: 表示判定2件成功。
- TypeScript型検査とVite本番ビルド成功。
- Playwright: 2件成功。人間のカード選択、AIで全15ターン完走、公開履歴の切替、終了後操作停止、390pxモバイル表示、比較実験と4グラフを確認。スクリーンショットも目視確認。
- CLIで50配札×6座席順=300試合を実行。集計・JSON保存込みで約2.49秒（約121試合/秒）。この端末での参考測定であり、戦略構成で変動する。

サンプル対戦（Random / Greedy / Heuristic、seed 42〜91）：ターン獲得率は30.5% / 37.5% / 31.9%、ゲーム勝率は40.3% / 38.7% / 33.7%。この少数サンプルで優劣は断定しないが、ターン獲得とゲーム勝利が異なる指標であることを観察できる。

## 現在の制限

- ルールは公開資料に基づく暫定採用部分を含み、原典全文との一致は未確認。
- 完全情報・カスタム情報モード、高度な推論、学習アルゴリズムはまだない。情報条件はimperfectとして保存・表示。
- バッチは単一プロセス。大量対戦の並列化やキャッシュ最適化は今後の拡張。
- 実験APIは1要求500配札まで。CLIでは大きな配札数を指定可能。非同期ジョブ・キャンセル・進捗表示は未実装。
- ゲームセッションはメモリ保持。サーバー再起動で失われる。実験結果はSQLiteに残る。
- ゲーム履歴の現在得点と過去の公開ターンは別表示。完全リプレイはPythonのresearch APIで保存・再生できるが、ファイル読み込み用UIはまだない。
- 順位別出現率、残りターン数別の行動分析、計算時間対勝率の散布図、推論精度推移は今後追加。
- FastAPIの依存からhttpxテストクライアントの非推奨警告が1件出るが、テストは成功。EChartsを含む初期ビルドサイズにも警告があり、配信最適化は未実施。

再現対象は配札・行動・得点・履歴。実測時間、UUIDは再現対象外。試合をまたぐ戦略の状態共有はせず、実験結果にはシード、座席順、相手構成、戦略バージョン、ルール、情報条件を保持する。
