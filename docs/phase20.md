## 目的と位置付け

6案はユーザーが提示した**未検証の仮説**であり、既知の定石や有効な戦術とは扱わない。各案を観測だけで計算できる代理評価へ具体化した。仮説の代理点と、対局後に測る終局報酬を区別する。代理点が高いことは、勝率・終局報酬が高いことを意味しない。

## 既存Heuristic・ScoreAwareとの関係

既存実装は変更していない。未知札数U、ある札より低い未知札L、高い未知札Hに対し、比較用のターン獲得確率は `p=2LH/(U(U−1))`。ScoreAwareは自分のラウンド得点が中央値以下なら獲得、上なら回避を目指し、`desire*p` を比較する。

Heuristicは同じ獲得・回避に加えて、累計得点が中央値より高ければ回避を優先する。ラウンド目標は `相手2人のラウンド得点平均 + (2−turn%3)*3`。距離項は `p*abs(自分点+札ランク−目標)+(1−p)*abs(自分点−目標)`、残り札項は「選択後の札のランク7からの平均距離」。最終的な独自評価は `desire*p − 距離/13 + 残り札項*0.03`。同点は既存どおり乱択する。

この目標・係数は既存コードの比較用基準で、理論上の最適値ではない。「中程度の札を温存」は、Heuristicの「7から遠い札を残す」項とは方向が違う。Theory Labはこの違いも検証可能にする。

## Registryと評価インターフェース

`strategies/theories.py` の `register_theory(definition, evaluator)` で、安定ID・日本語名・説明・根拠・利用情報・適用局面・パラメータ・評価式・版・既存機能との関係・限界を一度だけ登録する。`GET /api/theories` は同じ情報をUIへ返す。関数名やコード文字列をリクエストから実行する仕組みはない。

`evaluate_theory(observation, legal_action, spec)` は評価値、適用可否、説明、計算内訳を返す。合法手でない札、未知ID/版/パラメータ、範囲外・非有限値を拒否する。各評価値は−1〜+1。無効・重み0なら0で不適用。Registryの評価器にはGameや実際の隠し手札を渡さない。

設定例：

```json
{
  "tie_break": "seeded_random",
  "theories": [
    {"id":"reserve_strong","version":"1","enabled":true,"weight":1,"params":{"mode":"preserve","threshold":10}},
    {"id":"round_focus","version":"1","enabled":false,"weight":1,"params":{"mode":"round"}}
  ]
}
```

設定は省略既定値、数値表現、仮説順を正規化する。設定IDは正規化したJSONのSHA-256先頭16桁を含む。省略した重み1が再読込時1.0になってIDが変わる問題を検証中に発見し修正した。省略・明示・SQLite再読込の回帰テストを追加済み。開発途中の測定DBは削除せず保持し、報告用には別DBを使用した。

## 6仮説の定義

| ID | 仮説 | 代理評価と設定 | 主な限界 |
| --- | --- | --- | --- |
| `reserve_strong` | 強いカードの温存 | 選択後に残るrank≥thresholdの割合×`(14−turn)/14`。既定threshold10。preserveは正、consumeは負 | K最大でも最大札がターンを取るわけではない。残り札は全て使わず、2枚は残る |
| `reserve_middle` | 中程度の札の温存 | 選択後に残る中心±幅の札の割合×残り選択機会。既定中心7、幅2。preserve/consume | 中ランクが中位となる保証はない。スートも同ランクの大小に影響 |
| `round_focus` | 現在ラウンド重視 | 相手2人の現在点平均を目標とし、ターン獲得確率pで自分だけrank点増える期待距離を計算。距離/39の負値。modeはround/cumulative/both | 相手の得点変化を固定。ラウンドの中間獲得確率を直接計算するものではない |
| `cumulative_target` | 累積点からの逆算 | 下記の仮のラウンド終了モデルで累計目標からの期待距離を計算し、`39×残りラウンド数`で割って負値化 | 将来ラウンドを探索しない。最終勝率・到達可能性の厳密推定ではない |
| `public_memory` | 公開カードの記憶 | 未知札から重複なく2枚を一様出札する中位確率p。public=trueは公開札を除外、falseは現在の手札以外の52枚中の分布を使う | falseの仮想評価分布は既出札を含み得る。合法な世界のサンプラーではない |
| `opponent_targets` | 相手の目標推定 | 相手がラウンド中位以下なら獲得、上なら回避を望むと仮定し、未知札の出札重みを調整 | 実際の意図・手札・学習した傾向ではない。累計目標の推定は未実装 |

温存2案は最終選択turn14では不適用。そこで札を残しても、その後に再使用できないためである。温存札が未使用の2枚に入るだけというリスクもあり、温存の価値を証明した評価式ではない。

累計代理モデルは、相手ラウンド点を固定し、今ラウンドが終わると仮定する。自分の仮ラウンド点が相手2人の点の間にあればその点を仮の累計加算とし、そうでなければ0とする。pで獲得・非獲得を重み付けし、相手の現在累計平均との距離を求める。値は−1〜0へクリップする。高い累計を無条件に好まない一方、序盤に差がない局面では多数の同点を生み得る。これはエンジンの得点処理を置き換えるものではない。

相手目標モデルでは、未知札c自身を除いた一様出札でcが中位になる確率をqとし、獲得を望む相手の重みを `1+strength*q`、回避なら `1+strength*(1−q)` とする。strength既定1、範囲0〜4。相手2人を席番号順に重み付き・重複なしで仮想出札させ、自分の中位確率を求める。自分がラウンド中位以下なら正、上なら負。strength0は一様モデルに戻る。これは公開点からの明示的な仮定であり、相手の意図を把握したと表示しない。

## 重み・寄与・同点

合計は `sum(weight_i * value_i) / sum(abs(weight_i))`。分母は有効な仮説の重みの絶対値合計。不適用の値は0で、無効の重みは分母へ含めない。重みは−2〜+2の有限値、既定1。最適化した値ではない。各候補に仮説の素点・重み・正規化後寄与・適用可否を保存し、UIから展開する。

ラウンド重視と累計逆算は同じ公開得点・確率を使う。round_focusのcumulativeモードはcumulative_targetと同じ代理式、bothはラウンド式との平均である。併用すれば同じ情報・評価を重複加算するため、独立した証拠や相乗効果とは扱わない。公開記憶を無効にしても、他の有効な仮説が公開分布を使う場合、戦略全体が履歴を忘れるわけではない。記憶on/offの予備比較は単一public_memoryで行った。

直接選択は最大代理点を選び、1e−12以内の同点を既定でseed付き乱択する。仮説なしなら合法手の一様乱択という対照になる。カード順を対照にすると低い札を選び、温存を暗黙に実行する偏りがあるため、この既定を選んだ。`tie_break=card_order` も設定可能。評価関数は決定的、カード選択は同じrng条件で再現する。

## 戦略とHybrid統合

- `theory_policy`：単一または複数仮説の代理点で直接選択。登録既定は強い札の温存＋ラウンド重視。
- `theory_search`：同じTheory評価器をHybrid Aの優先順位へ注入。
- `theory_search_adaptive`：Theory順位をHybrid Cの適応配分へ注入。

HybridSearchの任意 `priority_evaluator` は、観測から全合法手の有限評価値と内訳を返す。未指定なら従来のHeuristicを使い、既定挙動は維持する。探索の最終選択は終局報酬平均だけで、Theory点は加算しない。予算・最低評価・一様サンプラー・継続戦略制限はPhase 19を再利用。探索最終同点は従来どおりカード順。仮説なし優先器もカード順の順位になるため、探索の対照と均等配分は同一ではない。均等方式を比較対象として別途追加できる。

通常対局・AI観戦・同一局面比較・図鑑・一括実験は登録既定値で利用可能。細かな仮説設定はTheory Lab、JSONまたはPythonから指定する。仮説ごとの戦略IDを大量登録しない。

## 統計とseed管理

全6席順を配札ごとに集約し、配札平均を独立標本とする。設定間は同じ配札・席順・相手・役割別初期rngを共有する。同点や戦略の出札が変わると、その後の乱数消費・局面は分岐し、完全同一の乱数消費を強制するものではない。

対応比較は基準SHA・ソースfingerprint・ルール/報酬版・情報条件・相手・方策seed・seed用途・共通配札・席順・予算条件を照合する。不一致なら拒否する。Theory設定の違いは検証対象として記録する。10配札未満・標本分散0の区間は非表示、10〜19は参考区間。2000回の配札単位ブートストラップというPhase 18方針を維持する。多数の仮説や重みを試す選択バイアス・多重比較は未補正。

用途別範囲は開発0〜999999、検証1000000〜1999999、最終2000000〜2999999。新しいTheory実験は用途を必須とし、範囲外の混入を拒否する。古い非Theory結果のunassignedは互換用に残す。同じ用途内のseed再使用は再現・対応比較のため許可し、独立追試と誤認しない。新しい範囲でも乱数としての母集団代表性を保証するわけではない。

用途の分離は情報へのアクセス制御ではない。最終評価を見た後に調整すれば過学習は防げない。開発で仮説を作り、検証で候補を選び、最終評価は条件を固定して最後に使う運用が必要。今回、検証用・最終評価用の測定や自動重み最適化は行っていない。
