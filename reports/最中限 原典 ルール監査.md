## 最終累計と勝敗後の報酬は別の量である

ラウンドrのターンtのカードをc(r,t,p)、中間カードの席をm(r,t)とする。現行エンジンの処理は次式で表せる。Rはラウンド内の数字点、Aはラウンドからの獲得点、Gは5ラウンド累計、Wはゲーム勝者集合である。

```text
v(r,t,p) = rank(c(r,t,p))  if p=m(r,t), else 0
R(r,p)   = Σ(t=1..3) v(r,t,p)
A(r,p)   = R(r,p) if R(r,p)=median(R(r,*)), else 0
G(p)     = Σ(r=1..5) A(r,p)
W        = {p | G(p)=median(G)}
```

各ターンの数字加算を先に行い、3回目ならRの中位判定とA加算、その後Rを0へ戻す。15回目にもこの通常の加算が一度行われる。残った2枚の点、固定3点、カード枚数ボーナス、勝者への他人のG合計、終局でのGの二重加算は現行処理にない。S1/S2はこのR→A→G→Wを支持する。[S1 p32 §3.2(3)–(5)](https://ipsj.ixsq.nii.ac.jp/record/58572/files/IPSJ-GI03010005.pdf)、[S2 p56 §2](https://ipsj.ixsq.nii.ac.jp/record/232248/files/IPSJ-WPRO2021010.pdf)

S1はWを確定した**後**、(6)と表2で別のゲーム報酬Uを定める。表2の要約は次のとおりで、各試合のU合計は0になる。これはGに追加して中位を再判定する手順ではない。[S1 p32(6)・p33表2](https://ipsj.ixsq.nii.ac.jp/record/58572/files/IPSJ-GI03010005.pdf)

| 勝者人数 | 各勝者のU | 各敗者のU | 監査用のG入力例と対応U（資料掲載例ではない） |
| --- | ---: | ---: | --- |
| 1 | +2 | -1 | G=(3,7,11)、W=P2、U=(-1,+2,-1) |
| 2 | +1 | -2 | G=(3,3,11)、W=P1/P2、U=(+1,+1,-2) |
| 3 | 0 | 敗者なし | G=(7,7,7)、W=全員、U=(0,0,0) |

現行APIの `game_scores`、SQLiteの `scores` と平均得点、分岐の平均得点・標準偏差・得点差・順位分布はGでありUではない。現行勝率はWに入る頻度で、共同勝者各人に1勝を数える。Uを別指標として後から算出してもWやその勝率は変わらない。しかし**勝率最大化と期待U最大化は異なる目的**である。例えば本人一人勝ち40%・他者一人勝ちで本人敗北60%なら期待U=0.4×2−0.6×1=0.2、本人を含む二人共同勝ち60%・他の二人が共同勝利して本人だけ敗北40%なら期待U=0.6×1−0.4×2=−0.2で、勝率順位と期待報酬順位が逆転する。全員勝利では勝率指標1、U=0になる。これは表2からの算術例で、実際の戦略性能測定ではない。

S1 §4.1の終盤探索は終局Uを使うため、抄録の負の期待値は非負のGが負になることを意味しない。S2は勝率評価を扱い§2にU表を載せないが、その理由や廃止を明記していない。S4の「勝者はその得点総計を得ます」だけからUを導けず、Gの追加再加算を導くこともできない。原案のU採用、GPCC競技への導入時期、記事がこの段階をどの意味で省略したかは未確認のままとする。

### 資料の局所例とエンジンの人工例を区別する

S2 p58 §5.3例(1)は3ターン目直前の点が本人0・相手5・8で、本人が♠4で獲得しても最小のままであると説明する。数式上R=(4,5,8)になり本人はラウンド勝者でない。相手の実提出3枚がこの記述だけでは定まらないため、完全なGame対戦の再現とは呼ばない。例(2)の0/3/10も、本人がA〜2またはJ〜Kで得点してもしなくても中位にならないという局所的説明である。[S2 p58 §5.3](https://ipsj.ixsq.nii.ac.jp/record/232248/files/IPSJ-WPRO2021010.pdf)

以下は監査担当が実際のエンジンで計算した人工例であり、資料から引用した対戦ではない。残りの手札は52枚の重複なし条件を満たすよう補充した。初期R=G=(0,0,0)からの3ターンは次のようになる。

| ターン | P1 / P2 / P3の提出 | 中間カード | 加算後R | 加算後G |
| --- | --- | --- | --- | --- |
| 1 | ♣8 / ♣K / ♣A | P1 ♣8 | (8,0,0) | (0,0,0) |
| 2 | ♦A / ♦8 / ♦K | P2 ♦8 | (8,8,0) | (0,0,0) |
| 3 | ♥A / ♥K / ♣3 | P3 ♣3 | (8,8,3) | (8,8,0) |

ラウンド勝者はP1/P2、各自身の8点を得る。次の観測Rは0、ゲームは未終了なので最終Wは空である。別の3ターンでP3だけが2、4、6を得るとR=(0,0,12)となりP1/P2が勝者だがA=(0,0,0)でGは増えない。

15ターンを通した例は `Game(0)` で全席が毎回 `hand[0]` を提出するもの。5ラウンド末のRは順に(2,0,2)、(0,0,13)、(0,0,18)、(23,0,0)、(0,12,21)、最終G=(2,12,2)、W=P1/P3となる。両者は通常得点順位では2–3位同点だがゲームの共同勝者である。S1表2を監査用に当てはめればU=(1,-2,1)だが、エンジンはこのUを保存しない。

到達可能な全員0の例もある。`deck()`の先頭17枚、次の17枚、次の17枚を各席へ配り最後の1枚を除外し、毎回各 `hand[0]` を出す。毎ターンP2が中位となり、各ラウンドRは(0,15,0)、(0,18,0)、(0,20,0)、(0,22,0)、(0,24,0)。毎回中央値0の両人へ0加算なのでG=(0,0,0)、全員勝者となる。対照的にラウンドR=(0,0,0)は、毎ターン正の数字が一人へ入るため有効な3ターンでは到達しない。純関数の0入力検証と実到達局面を区別する。
